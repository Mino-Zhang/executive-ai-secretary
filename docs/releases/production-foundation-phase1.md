## 首次正式镜像发布前的外部设置

本机部署不依赖以下 GitHub 设置。首次发布正式镜像前，应在仓库中完成：

1. 创建 `production-images` Environment，启用非空必需审批人、禁止自我审批，并将定制部署来源设为 branch 类型的 `main` 与 Tag 类型的 `production-v*`。
2. Environment 完成复核后，由仓库管理员显式设置 Repository Variable `PRODUCTION_IMAGE_RELEASES_ENABLED=true`。
3. 为 `main` 和 `production-v*` 配置 Ruleset，要求 CI 通过并限制直接推送或删除。
4. 由受保护的发布工作流生成并签名 release bundle，再按 bundle 中的精确 digest 部署。

截至本验收日，GitHub API 显示仓库中尚无 Environment，且未启用发布变量。发布 Workflow 因此默认关闭：任何 Tag 或人工触发都不会启动带 `packages: write` / `id-token: write` 的 Job，也不会创建或发布镜像。
