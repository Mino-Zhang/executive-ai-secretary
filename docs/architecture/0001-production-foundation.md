# ADR 0001：生产底座与本机交付边界

- 状态：已确认
- 日期：2026-07-27
- 决策人：产品负责人
- 适用阶段：生产化第一阶段

## 背景

当前版本是确定性前端 Demo。生产化第一阶段需要在不改变已确认产品体验、也不污染在线 Demo 的前提下，建立可真实登录、可持久化、可审计、可备份的本机生产底座，并为后续客户快速部署保留一致的交付形态。

## 已确认决策

1. 当前 `main` 的 `fcffc88` 冻结为 `demo-v1.0.0`，生产工作在 `codex/production-foundation` 独立分支进行。
2. 第一阶段仅允许从演示者本机访问，所有对外端口默认绑定 `127.0.0.1`；不提供局域网或公网访问。
3. 本机保留两个完全隔离的运行环境：
   - `local-demo`：只允许使用脱敏演示数据，并在界面和日志中明确标识。
   - `customer-template`：空数据库、空文件卷，不包含演示数据、演示凭据或默认口令。
4. 身份默认采用企业管理员预置账号、全局唯一登录邮箱、Argon2id 密码哈希、不透明服务端 Session、首次登录强制改密，并预留 OIDC/企业 SSO 适配接口。若未来允许同邮箱进入多个租户，必须先引入显式租户选择或企业 SSO 标识，不能让登录查询产生歧义。
5. 授权采用角色与数据范围双重校验。角色为 `executive`、`enterprise_admin`、`fde`；事业部选项及可查询范围只能来自服务端授权结果。
6. 文件字节写入私有服务端卷，使用应用层存储适配器与 AES-GCM 静态加密；数据库仅保存元数据、所有权和处理状态。
7. PostgreSQL 是生产数据唯一事实源；浏览器存储只允许保存主题等非权威界面偏好。
8. 第一阶段不接入真实 Hermes、MCP、企业经营数据源、飞书推送或文件正文解析。接口与任务状态必须真实存在，但不可用能力必须明确返回“尚未配置”，不得以固定样本伪装成功。
9. 使用 Docker Compose 保持本机与客户 Linux 服务器的一致交付形态，同时兼容 Apple Silicon 和 `linux/amd64`。
10. 离线安装包不在第一阶段制作；第五阶段完成后，基于相同镜像、迁移和配置契约制作离线交付包。

## 安全不变量

- 生产模式启动时如检测到演示种子开关、演示口令或不安全密钥，必须拒绝启动。
- 企业管理员和 FDE 默认不能读取高层会话正文、长期记忆正文和上传文件正文。
- 所有写操作必须同时经过身份、CSRF、资源所有权或角色、数据范围校验，并写入审计事件。
- 密钥不得进入 Git、前端包、日志、备份清单或 API 响应。
- 备份与恢复按环境隔离，恢复脚本必须拒绝跨环境误恢复，除非显式提供受控覆盖参数。

## 生产就绪定义（第一阶段）

- 未登录用户不能访问业务 API；首次改密前不能访问业务功能。
- 会话、消息、项目、文件元数据、记忆、简报、任务和审计可持久化并按用户/范围隔离。
- `local-demo` 与 `customer-template` 可同时存在、独立启动、独立备份和独立恢复。
- 本机重启和容器重建不丢失数据；完成至少一次自动化恢复验收。
- CI 能验证前端、后端、迁移、Compose 配置、镜像构建及密钥泄漏基础规则。
- 生产前端永不自动回退到 `prototype-data.ts`。

## 后续阶段边界

第一阶段交付的是可信的系统底座，不等同于完整业务智能。Hermes/MCP、真实经营数据、文件解析、主动简报与飞书等能力在后续阶段逐项接入，并复用本阶段的身份、权限、数据、任务和审计契约。
