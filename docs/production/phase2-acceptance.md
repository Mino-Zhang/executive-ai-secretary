## Anspire 全球模型通道

- 唯一模型供应商为 Anspire，正式网关固定为 `https://open-gateway.anspire.ai/v6`。
- 已通过真实 `GET /v6/models` 响应核对后端目录，共纳入 53 个当前模型。
- 39 个聊天与推理模型可以在管理端选择；6 个图像、4 个视频、2 个 Embedding 和 2 个 Rerank 模型保留在后端能力目录，但不会误入聊天端点。
- 默认模型为 `glm-5.2`；真实连接测试通过，实测延迟 4435 ms。
- 默认 `glm-5.2` 的日常路由、规划与经营回答通过 Hermes custom-provider 配置关闭深度思考，保留 Harness、MCP 规划、证据和权限链；其他目录模型保持各自默认推理行为，不同 Profile 均有独立输出预算。
- 模型配置必须经过“保存、测试、启用”三步；更换模型或凭证后自动停用并要求重新测试。
- API Key 使用企业 ID 作为附加认证数据执行 AES-GCM 加密；数据库、环境文件、浏览器存储、日志、回答证据和 Git 均不保存明文。
- Hermes 不挂载持久模型凭证；API 只为单次请求解密，并以带时间戳和请求 ID 的 HMAC 签名传递，重复请求会被拒绝。
- Anspire 不可用时明确失败，不回退到其他模型供应商，也不生成伪回答。

## 最小权限数据库角色

六个常驻服务使用独立数据库账号：

- API：应用数据读写，审计事件不可修改。
- MCP Hub：仅查询授权经营维表和事实表，不能读取用户或写入事实。
- Ingestion Worker：写入同步批次、事实、快照、状态和检查点。
- Scheduler：只管理计划、运行记录和任务队列，不读取经营事实。
- Assistant Worker：处理会话、消息、路由、证据和回答任务。
- File Worker：仅保留历史环境恢复兼容；当前无上传入口、无新文件任务。

原通用运行角色只供受控的一次性 Seed、Bootstrap 和源库管理命令使用。正向与反向权限测试均已通过；当前隔离为表级最小权限，任务队列内的 `job_type` 行级边界仍由 Worker 白名单控制。
